# P1.1 — Schema name validated and quoted in DDL (SQL injection fix)

## What changed

`PostgresMigrator.Migrate()` and `PostgresMigrator.GetPendingMigrations()` now validate
the `schema` parameter against the allowlist `^[a-z][a-z0-9_]{0,62}$` before issuing any
database call. Schema names that do not match throw `ArgumentException`.

`PostgresMigrator.EnsureSchemaExists()` (internal) now uses a double-quoted PostgreSQL
identifier in the `CREATE SCHEMA IF NOT EXISTS` DDL statement.

## Why

Previously the schema name was interpolated unquoted into a raw DDL string:
```csharp
cmd.CommandText = $"CREATE SCHEMA IF NOT EXISTS {schema}";
```
An attacker (or mis-configured environment) supplying a crafted schema name could execute
arbitrary SQL at startup with the service's DB credentials. Severity: **critical** — exploitable
wherever the schema name derives from config, environment variables, or external input.

## Impact

**Breaking for callers that pass schema names outside the allowlist pattern.**

| Schema name | Before | After |
|-------------|--------|-------|
| `"orders"` | Accepted | Accepted (no change) |
| `"my_schema"` | Accepted | Accepted (no change) |
| `"MySchema"` (uppercase) | Accepted | `ArgumentException` |
| `"orders-v2"` (hyphen) | Accepted | `ArgumentException` |
| `"public"` | Accepted | Accepted (no change) |

## Migration

Lowercase your schema name and replace any hyphens with underscores:
- `"MySchema"` → `"myschema"`
- `"orders-v2"` → `"orders_v2"`

If the schema was already created in PostgreSQL with a non-conforming name, rename it first
(or drop and recreate with migrations):
```sql
ALTER SCHEMA "MySchema" RENAME TO myschema;
```
