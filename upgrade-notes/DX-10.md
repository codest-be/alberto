# DX-10 — `Register*` methods removed from `IEventStore`; use `IEventStoreConfigurator`

## What changed

Three setup-time methods have been removed from `IEventStore`:

- `RegisterInlineProjection<TState, TProjection>(IStateStore<TState>)`
- `RegisterInlineProjection(IInlineProjection)`
- `RegisterPostAppendHandler(IPostAppendHandler)`

They now live on a new `IEventStoreConfigurator` interface (in `Alberto.Dcb`).
The concrete store classes (`PostgresEventStore`, `InMemoryEventStore`) implement **both**
`IEventStore` and `IEventStoreConfigurator`.

The `RegisterEfInlineProjection` extension methods in `Alberto.Dcb.EntityFramework` have been
updated to extend `IEventStoreConfigurator` rather than `IEventStore`.

## Why

`IEventStore` is the runtime consumer surface — it should only expose `AppendAsync`,
`StreamAsync`, `StreamAllAsync`, and `GetLastPositionAsync`. Exposing setup-only methods on the
same interface lets runtime code accidentally register projections or handlers after the store has
already started serving requests, leading to unpredictable ordering or missed events.
Separating concerns at the interface level makes the intent explicit and prevents the mistake
entirely at compile time.

## Impact

This is a **breaking change** for any code that:

1. Calls `Register*` through a variable typed as `IEventStore` (rather than through the concrete
   type).
2. Extends `RegisterEfInlineProjection` callers that type the first argument as `IEventStore`.
3. Implements `IEventStore` in a custom store class and has the `Register*` methods there — the
   custom class no longer satisfies the interface via those methods.

Code that calls `Register*` directly on `new PostgresEventStore(...)` or
`new InMemoryEventStore(...)` (as in tests) is **not affected** — the methods still exist on the
concrete types.

## Migration

### If you call Register* through IEventStore

**Before:**
```csharp
IEventStore store = ...; // resolved from DI or created directly
store.RegisterInlineProjection(myProjection);
store.RegisterPostAppendHandler(myHandler);
```

**After:**
```csharp
// Option A — cast (appropriate in builder/factory code where the concrete type is known)
if (store is IEventStoreConfigurator configurator)
{
    configurator.RegisterInlineProjection(myProjection);
    configurator.RegisterPostAppendHandler(myHandler);
}

// Option B — resolve IEventStoreConfigurator directly if you own the construction
IEventStoreConfigurator configurator = new PostgresEventStore(backend);
configurator.RegisterInlineProjection(myProjection);
```

### If you use RegisterEfInlineProjection

**Before:**
```csharp
IEventStore store = ...;
store.RegisterEfInlineProjection<TEntity, TProjection, TDbContext>(serviceProvider);
```

**After:**
```csharp
// The extension method is now on IEventStoreConfigurator
IEventStoreConfigurator configurator = (IEventStoreConfigurator)store; // safe cast for built-in stores
configurator.RegisterEfInlineProjection<TEntity, TProjection, TDbContext>(serviceProvider);
```

### If you implement a custom IEventStore

If you have a custom class that implemented `IEventStore` and included `Register*` methods to
satisfy the interface, those methods are no longer required by `IEventStore`. If you want your
custom store to support setup-time registration, implement `IEventStoreConfigurator` explicitly:

```csharp
public class MyCustomEventStore : IEventStore, IEventStoreConfigurator
{
    // IEventStore members (AppendAsync, StreamAsync, StreamAllAsync, GetLastPositionAsync) ...

    // IEventStoreConfigurator members
    public void RegisterInlineProjection<TState, TProjection>(IStateStore<TState> stateStore) ...
    public void RegisterInlineProjection(IInlineProjection projection) ...
    public void RegisterPostAppendHandler(IPostAppendHandler handler) ...
}
```
