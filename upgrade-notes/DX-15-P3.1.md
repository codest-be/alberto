# DX-15 / P3.1 — Async-suffix rename on IEventStoreBackend + IEventStoreHeadBackend split

**Severity**: BREAKING — every implementer and every direct call site of the renamed
methods must be updated. Usages through `IEventStore` (the high-level public API) are
unaffected; only integrators that depend on `IEventStoreBackend` directly need to act.

---

## What changed

### DX-15 — Consistent `Async` suffix on `IEventStoreBackend`

The four methods that previously lacked the `Async` suffix were renamed:

| Before | After |
|--------|-------|
| `Stream(...)` | `StreamAsync(...)` |
| `StreamAll(...)` | `StreamAllAsync(...)` |
| `Append(...)` | `AppendAsync(...)` |
| `GetLastPosition(...)` | `GetLastPositionAsync(...)` |

`GetPositionsAsync` and `GetStableHeadAsync` already had the suffix and were not changed
(they moved to `IEventStoreHeadBackend` — see P3.1 below).

### P3.1 — `IEventStoreHeadBackend` interface extracted

`GetPositionsAsync` and `GetStableHeadAsync` were removed from `IEventStoreBackend`
and placed on a new dedicated interface:

```csharp
public interface IEventStoreHeadBackend
{
    Task<IReadOnlyList<long>> GetPositionsAsync(
        long afterPosition, int windowSize, CancellationToken cancellationToken = default);

    Task<long> GetStableHeadAsync(
        long afterPosition, CancellationToken cancellationToken = default)
        => Task.FromResult(long.MaxValue);   // default: no barrier
}
```

`IEventStoreBackend` now has exactly four methods (`StreamAsync`, `StreamAllAsync`,
`AppendAsync`, `GetLastPositionAsync`).

All built-in backends (`InMemoryEventStoreBackend`, `PostgresEventStoreBackend`,
`TenantEventStoreDecorator`, `InterceptingEventStoreBackend`) implement **both**
interfaces. `EventStoreHead` now accepts `IEventStoreHeadBackend` instead of
`IEventStoreBackend`.

---

## Migration steps

### 1. Custom `IEventStoreBackend` implementations

Add `IEventStoreHeadBackend` to the `implements` list:

```csharp
// Before
public class MyBackend : IEventStoreBackend
{
    public Task<IReadOnlyCollection<IEventEnvelope>> Stream(...) { ... }
    public Task<IReadOnlyCollection<IEventEnvelope>> StreamAll(...) { ... }
    public Task<IReadOnlyCollection<IEventEnvelope>> Append(...) { ... }
    public Task<long> GetLastPosition(...) { ... }
    public Task<IReadOnlyList<long>> GetPositionsAsync(...) { ... }
    public Task<long> GetStableHeadAsync(...) { ... }
}

// After
public class MyBackend : IEventStoreBackend, IEventStoreHeadBackend
{
    public Task<IReadOnlyCollection<IEventEnvelope>> StreamAsync(...) { ... }
    public Task<IReadOnlyCollection<IEventEnvelope>> StreamAllAsync(...) { ... }
    public Task<IReadOnlyCollection<IEventEnvelope>> AppendAsync(...) { ... }
    public Task<long> GetLastPositionAsync(...) { ... }
    // GetPositionsAsync and GetStableHeadAsync move to IEventStoreHeadBackend:
    public Task<IReadOnlyList<long>> GetPositionsAsync(...) { ... }
    // GetStableHeadAsync is optional — the interface default returns long.MaxValue.
}
```

### 2. Direct call sites on `IEventStoreBackend`

Rename each method at the call site:

```csharp
// Before
var events = await backend.Stream(query, ct: ct);
var all    = await backend.StreamAll(ct: ct);
var result = await backend.Append(events, query, expectedPos, ct);
var pos    = await backend.GetLastPosition(ct);

// After
var events = await backend.StreamAsync(query, cancellationToken: ct);
var all    = await backend.StreamAllAsync(cancellationToken: ct);
var result = await backend.AppendAsync(events, query, expectedPos, ct);
var pos    = await backend.GetLastPositionAsync(ct);
```

### 3. Calls to `GetPositionsAsync` / `GetStableHeadAsync` on an `IEventStoreBackend` reference

These methods are no longer on `IEventStoreBackend`. Cast to `IEventStoreHeadBackend`:

```csharp
// Before (IEventStoreBackend reference)
var positions = await backend.GetPositionsAsync(after, windowSize, ct);

// After — cast to the head interface
var positions = await ((IEventStoreHeadBackend)backend).GetPositionsAsync(after, windowSize, ct);
```

All built-in backends implement both interfaces, so the cast is always safe when
using an Alberto-provided backend.

### 4. Test fakes for `EventStoreHead`

`EventStoreHead` now takes `IEventStoreHeadBackend`. Fakes that previously implemented
the full `IEventStoreBackend` to satisfy the constructor can now implement the smaller
interface:

```csharp
// Before
private sealed class FakeBackend : IEventStoreBackend
{
    public Task<IReadOnlyList<long>> GetPositionsAsync(...) { ... }
    public Task<long> GetStableHeadAsync(...) { ... }
    // Unused stubs required by IEventStoreBackend:
    public Task<IReadOnlyCollection<IEventEnvelope>> StreamAsync(...) => ...;
    public Task<IReadOnlyCollection<IEventEnvelope>> StreamAllAsync(...) => ...;
    public Task<IReadOnlyCollection<IEventEnvelope>> AppendAsync(...) => ...;
    public Task<long> GetLastPositionAsync(...) => ...;
}

// After — only the two methods EventStoreHead actually uses
private sealed class FakeBackend : IEventStoreHeadBackend
{
    public Task<IReadOnlyList<long>> GetPositionsAsync(...) { ... }
    public Task<long> GetStableHeadAsync(...) { ... }
}
```

### 5. `ControlLoopBuilder` / custom orchestration

If you resolve `IEventStoreBackend` from DI and pass it to `new EventStoreHead(...)`,
add a cast:

```csharp
var backend    = services.GetRequiredService<IEventStoreBackend>();
var headBackend = backend as IEventStoreHeadBackend
    ?? throw new InvalidOperationException("Backend must implement IEventStoreHeadBackend");
var head = new EventStoreHead(headBackend, refreshInterval);
```

`ControlLoopBuilder` already does this cast internally; only custom orchestration
code that constructs `EventStoreHead` directly is affected.

---

## Why these changes were made

**DX-15**: `IEventStore` (the high-level public API) consistently uses the `Async`
suffix. `IEventStoreBackend` did not. The inconsistency made it easy to confuse the
two interfaces and caused `Async`-lint tools to flag four methods per implementation.

**P3.1**: `GetPositionsAsync` and `GetStableHeadAsync` are only ever called by
`EventStoreHead`. Placing them on `IEventStoreBackend` forced every implementer
— including simple test fakes — to provide two methods it never uses. Moving them
to a dedicated `IEventStoreHeadBackend` makes the contract surfaces explicit and
lets subscriber-only fakes skip the append/read surface entirely.
