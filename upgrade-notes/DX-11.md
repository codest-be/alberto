# DX-11 — `[Tag]` no longer accepted on bare primary-constructor parameters

## What changed

`AttributeUsage` on `TagAttribute` previously listed `AttributeTargets.Parameter`.
That target has been removed; only `AttributeTargets.Property` is now valid.

## Why

Tag extraction reads **properties** via reflection (`GetProperties()`).
Applying `[Tag(...)]` directly to a primary-constructor parameter (without the
`[property:]` attribute specifier) placed the attribute on the *parameter*, not the
synthesised property, so no tags were ever extracted — silently, at runtime.
Restricting the target to `Property` turns that silent mis-use into a compile-time error.

## Migration

If you had any parameter-targeted usages, add the `property:` specifier:

```csharp
// Before (compiled but produced no tags):
public record OrderPlaced(
    [Tag("order")] Guid OrderId) : IEvent;

// After (correct — attribute lands on the synthesised property):
public record OrderPlaced(
    [property: Tag("order")] Guid OrderId) : IEvent;
```

The `[property: Tag(...)]` form was already shown in the XML-doc example
and has always produced the correct behaviour; only the bare `[Tag(...)]`
on parameters is now rejected by the compiler.
